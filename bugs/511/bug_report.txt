RuntimeError: Found invalid non-sorted temporal neighborhood

BODY
### 🐛 Describe the bug

I'm have an issue with distributed computing on a temporal graph using [PyTorch Geometric](https://github.com/pyg-team/pytorch_geometric/tree/master/examples/distributed/pyg). After modifying the demo to run on my own temporal graph data, I met an error when running the distributed computing process.

The error occurs when executing the `neighbor_sampler.py` file, specifically at lines [390](https://github.com/pyg-team/pytorch_geometric/blob/1ab39939d3ef44afa816b1bec4a84c957ad990f2/torch_geometric/sampler/neighbor_sampler.py#L390). The error message is:
```
Traceback (most recent call last):
  File "<string>", line 1, in <module>
  File "/anaconda/envs/exphormer/lib/python3.10/site-packages/torch/_ops.py", line 1116, in __call__
    return self._op(*args, **(kwargs or {}))
RuntimeError: Found invalid non-sorted temporal neighborhood
```
After attempting to debug the issue, I suspect that the problem lies in the `self.row` (Line [222](https://github.com/pyg-team/pytorch_geometric/blob/1ab39939d3ef44afa816b1bec4a84c957ad990f2/torch_geometric/sampler/neighbor_sampler.py#L222) in  `neighbor_sampler.py`) index range, which leads to the value at line [370](https://github.com/pyg-team/pytorch_geometric/blob/1ab39939d3ef44afa816b1bec4a84c957ad990f2/torch_geometric/sampler/neighbor_sampler.py#L370).


I would appreciate any guidance on how to resolve this issue or if distributed computing supports temporal neighborhoods.
