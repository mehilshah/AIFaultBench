### Reproduction

The below script will hang and print out a pickling error, rather than terminating with an informative error.

Changing `CATCH_EXCEPTION = True` will not hang, and additionally print out the full exception with stack trace to the offending line as expected.

```
import safetensors, safetensors.torch
import torch.utils.data

NUM_ITEMS = 5
CATCH_EXCEPTION = False

class SafeTensorDataset(torch.utils.data.Dataset):
  def __init__(self):
    super().__init__()
    # Write safetensors file
    data = { str(i): torch.ones((1, )) for i in range(NUM_ITEMS) }
    safetensors.torch.save_file(data, "my_tensor.safetensors")
    
  def __getitem__(self, idx):
    with safetensors.safe_open(
      "my_tensor.safetensors", framework="pt", device="cpu"
    ) as f:
      if CATCH_EXCEPTION:
        try:
          return f.get_tensor(str(idx))
        except Exception as e:
          raise Exception(str(e))
      else:
        return f.get_tensor(str(idx))
  def __len__(self):
    return NUM_ITEMS + 1

if __name__ == "__main__":
  dataset = SafeTensorDataset()
  dataloader = torch.utils.data.DataLoader(
    dataset,
    num_workers=2
  )

  for i, batch in enumerate(dataloader):
    print(f"Retrieved batch {i}")
```

### Expected behavior

Because `SafetensorError` can't be pickled, if it gets thrown from inside a PyTorch dataset running under a multi-worker dataloader, the exception does not get propagated up to the main process and the dataloader hangs. If the exception were pickleable, then it would be received and terminate with the error message.

Although in the reproduction this still provides a PickleError, in our production system, even this error did not get printed. In that case, it is very difficult to debug the deadlocked dataloader processes and identify the source of the bug.
