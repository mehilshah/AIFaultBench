TITLE
Adding constraints to multi-table synthesizer in multiple steps causes fit to crash

BODY
### Environment Details

Please indicate the following details about the environment in which you found the bug:

* SDV version:  1.28.0

### Error Description

If I add constraints that are applied to a single table to a multi-table synthesizer in steps, it crashes. By in steps, I mean if I add some constraints with one call and then the rest later. If I add the same constraints all at once, even in the same order, it works.

This seems to be due to a call being made to self._initialize_models inside the function that adds the constraints.
https://github.com/sdv-dev/SDV/blob/934ba74c5e3f0bc3c07f3b8e2ad204d3fec6006e/sdv/multi_table/base.py#L233

### Steps to reproduce

Below I show this by:

1. Creating two multi-table synthesizers
2. Making a list of constraints
3. To one synthesizer, I add the whole list at once
4. To the other, I add some constraints with one call, and then the rest in a second call
5. I try to fit both synthesizers. The second one crashes

```python

detailed_tables = [
    'regular_season_detailed_results',

        Inequality(

            high_column_name='wfga',
            strict_boundaries=False,  # Made can equal attempted in theory
            table_name=table_name
        )
    )
    print(f"Added constraint: wfgm <= wfga to {table_name}")

        Inequality(
            low_column_name='lfgm',

            strict_boundaries=False,

    print(f"Added constraint: lfgm <= lfga to {table_name}")

# 3-pointers (winner and loser)
for table_name in detailed_tables:
    constraints.append(
        Inequality(
            low_column_name='wfgm3',

    print(f"Added constraint: wfgm3 <= wfga3 to {table_name}")

        Inequality(
            low_column_name='lfgm3',

synthesizer.add_constraints(constraints)
```
