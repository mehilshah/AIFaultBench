# recovered-from-issue: https://github.com/PythonOT/POT/issues/418

TITLE
Wrong number of projections for sliced Wasserstein with predefined projections

BODY
The number of projections when using ```ot.sliced.sliced_wasserstein_distance``` with predefined projection matrix is not correct.  See the following example:
```python
import numpy as np
import ot

n_projections = 10
seed = 12
X = np.array([[1,2],[4,5],[6,-8]], dtype=float)
Y = np.array([[0,2],[14,52],[3,-12]], dtype=float)
cost1, log1 = ot.sliced.sliced_wasserstein_distance(X,Y, seed=seed, n_projections=n_projections, log=True)
P = ot.sliced.get_random_projections(X.shape[1], n_projections=10, seed=seed)
cost2, log2 = ot.sliced.sliced_wasserstein_distance(X,Y, projections=P, log=True)

print(np.linalg.norm(log1['projections']-log2['projections']))#same projection matrix
print(np.abs(cost1-cost2))#but different cost
```
Indeed when using ```projections=P``` the number of projections remains unchanged(equal to the default value) so that the normalization in https://github.com/PythonOT/POT/blob/0411ea22a96f9c22af30156b45c16ef39ffb520d/ot/sliced.py#L156
is not correct.

I will propose a PR to solve this issue.
