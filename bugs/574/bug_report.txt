### 🐛 Describe the bug

Model [`poolside/Laguna-XS.2-FP8`](https://huggingface.co/poolside/Laguna-XS.2-FP8) produces gibberish output, while running with vLLM 0.23.0 with flashinfer attention backend on H200

The server to run:
```
export CUDA_VISIBLE_DEVICES=0
uv run --no-project --python 3.12 --with "vllm==0.23.0" \
    vllm serve \
        poolside/Laguna-XS.2-FP8 \
        --served-model-name poolside/Laguna-XS.2-FP8 \
        --tensor-parallel-size 1 \
        --trust-remote-code \
        --kv-cache-dtype fp8 \
        --max-model-len 4096 \
        --gpu-memory-utilization 0.85 \
        --attention-backend FLASHINFER
```

The easiest way is to observe gsm8k scores: command

```
uv run --no-project --python 3.12 --with "lm-eval[api]" \
    lm_eval \
        --model local-completions \
        --model_args "model=poolside/Laguna-XS.2-FP8,base_url=http://127.0.0.1:8000/v1/completions,num_concurrent=128" \
        --tasks gsm8k \
        --batch_size auto
```

produces

```
|Tasks|Version|     Filter     |n-shot|  Metric   |   |Value |   |Stderr|
|-----|------:|----------------|-----:|-----------|---|-----:|---|-----:|
|gsm8k|      3|flexible-extract|     5|exact_match|↑  |0.0053|±  |0.0020|
|     |       |strict-match    |     5|exact_match|↑  |0.0015|±  |0.0011|
```

Whereas the expected value should be something like this:
```
|Tasks|Version|     Filter     |n-shot|  Metric   |   |Value |   |Stderr|
|-----|------:|----------------|-----:|-----------|---|-----:|---|-----:|
|gsm8k|      3|flexible-extract|     5|exact_match|↑  |0.2835|±  |0.0124|
|     |       |strict-match    |     5|exact_match|↑  |0.2729|±  |0.0123|
```

Note:
* this bug appears regardless of CUDA graphs or eager mode
* with TRITON_ATTN attention backend server crashes
* with FLASH_ATTN attention backend server produces correct results
* this bug doesn't appear on vLLM 0.22.0 (for all three aforementioned attention backends FLASHINFER / TRITON_ATTN / FLASH_ATTN)

Overall, looks like bugfix #42650 works and fixes #41651 in vLLM 0.22.0, but then everything breaks between 0.22.0 and 0.23.0
So, maybe it's a duplicate of #41651, but under different circumstances
