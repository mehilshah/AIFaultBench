### Reproduction

```python
from accelerate import Accelerator
from accelerate.utils import ProjectConfiguration
import torch

config = ProjectConfiguration(total_limit=3, automatic_checkpoint_naming=True)
accelerator = Accelerator(project_dir='./total_limit_test', project_config=config)

model = torch.nn.Linear(1, 1)
optimizer = torch.optim.Adam(params=model.parameters())
dataloader = torch.utils.data.DataLoader(None)
scheduler = torch.optim.lr_scheduler.ConstantLR(optimizer)

model, optimizer, dataloader, scheduler = accelerator.prepare(
     model, optimizer, dataloader, scheduler
)

for _ in range(20):
    accelerator.save_state()
```

### Expected behavior


When `total_limit` and `automatic_checkpoint_naming` are set in `ProjectConfiguration`, `save_state` should automatically delete old checkpoints keeping only `total_limit` latest ones. However because checkpoints are [sorted alphabetically](https://github.com/huggingface/accelerate/blob/3533e2b0b167238fcdd3c636dcf6c3c6de983efa/src/accelerate/accelerator.py#L2169) instead of numerically checkpoints with less digits are kept instead of latest ones. The reproduction example saves state 20 times and 8, 9 and 19 checkpoints are left at the end instead of three latest.
