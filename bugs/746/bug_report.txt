### Reproduction Steps / Example Code (Python)

```python
import asyncio
from langchain_core.retrievers import BaseRetriever
from langchain_core.documents import Document
from langchain.retrievers import EnsembleRetriever


class WeirdRetriever(BaseRetriever):
    def _get_relevant_documents(self, query, *, run_manager=None):
        return [42]

    async def _aget_relevant_documents(self, query, *, run_manager=None):
        return [42]


ensemble = EnsembleRetriever(retrievers=[WeirdRetriever()], weights=[1.0])

# Sync path: no crash, 42 passes through unchanged
ensemble.invoke("test")

# Async path: raises ValidationError
asyncio.run(ensemble.ainvoke("test"))
```

### Error Message and Stack Trace (if applicable)

```shell
pydantic_core._pydantic_core.ValidationError: 1 validation error for Document
  page_content
    Input should be a valid string [type=string_type, input_value=42, input_type=int]
```

### Description

I noticed that rank_fusion (sync) and arank_fusion (async) use different
conditions when normalizing retriever outputs to Documents.

rank_fusion uses:   isinstance(doc, str)          — only wraps bare strings
arank_fusion uses:  not isinstance(doc, Document) — wraps everything that
                                                     isn't a Document

So if a retriever returns anything that isn't a string or a Document, the
async path tries to call Document(page_content=<that value>) and Pydantic
raises a ValidationError immediately. The sync path just passes it through
unchanged, so the behavior is inconsistent between the two methods.

Expected: both paths apply the same normalization — arank_fusion should use
isinstance(doc, str) to match rank_fusion.
