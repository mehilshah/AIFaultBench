### 🐛 Describe the bug

### Description
`AsyncLLM.pause_generation(clear_cache=True)` appears to clear EngineCore/backend multimodal cache state, but does not clear the frontend sender multimodal processor cache. This can desynchronize the P0 sender cache from the P1 receiver/backend cache.

### Relevant Code
`AsyncLLM.pause_generation()` only forwards `clear_cache` to EngineCore:

```python
await self.engine_core.pause_scheduler_async(mode=mode, clear_cache=clear_cache)
```

It does not call:

```python
self.renderer.clear_mm_cache()
```

By contrast, `AsyncLLM.reset_mm_cache()` clears both sides:

```python
self.renderer.clear_mm_cache()
await self.engine_core.reset_mm_cache_async()
```

### Expected Behavior
`pause_generation(clear_cache=True)` should keep frontend and backend multimodal cache state synchronized, likely by clearing the sender multimodal cache when backend multimodal cache state is cleared.

### Actual Behavior
Backend multimodal cache state is cleared through EngineCore, but frontend sender cache state is left intact.

### Impact
The multimodal cache contract says P0 and P1 caches must remain mirrored. Sender-side cache hits can cause P0 to omit multimodal payloads because it assumes P1 already has them. After backend-only clearing, that assumption is broken. It causes errors like

### Possible Fix
Update `AsyncLLM.pause_generation()` so that when `clear_cache=True`, it also clears the renderer multimodal cache, similar to `reset_mm_cache()`:

```python
if clear_cache:
    self.renderer.clear_mm_cache()
await self.engine_core.pause_scheduler_async(mode=mode, clear_cache=clear_cache)
```

The exact ordering may need care around in-flight requests and pause modes, like `wait` and `keep`.
