TITLE

### Reproduction

from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model = AutoModelForCausalLM.from_pretrained("gpt2")
model.generation_config.cache_implementation = "static"
model.forward = torch.compile(model.forward, backend="inductor")

tokenizer = AutoTokenizer.from_pretrained("gpt2")
input_ids = tokenizer("Hello world", return_tensors="pt").input_ids

# First call: works
output1 = model.generate(input_ids, max_new_tokens=1, do_sample=False)
print("First call OK:", output1.shape)

# Second call: CRASHES
output2 = model.generate(input_ids, max_new_tokens=1, do_sample=False)
print("Second call OK:", output2.shape)

**Note**: On CUDA this may not crash due to CUDA graph replay masking the bug. 
To reproduce on CUDA, you can add a `torch._dynamo.reset()` between calls to force retracing.

### Expected behavior

Multiple `model.generate()` calls with static cache and `torch.compile` should work
without crashing, regardless of the backend device.

## Root Cause Analysis

1. `cache_utils.py` line 383: `self.cumulative_length = torch.tensor([0], dtype=int)`
   - Comment says: "Very important that it's a tensor here, to avoid recompiling"
   
2. `cache_utils.py` line 461: `get_seq_length()` returns this tensor directly
   - Return type annotation says `-> int` but actual return is `torch.Tensor`

3. `generation/utils.py` `_prefill()`: Uses `past_length` in int arithmetic
   - `next_sequence_length = input_ids.shape[1] - past_length` → produces tensor

4. `generation/utils.py` line 502: `prepare_inputs_for_generation(next_sequence_length: int | None)`
   - Type contract violated: receives tensor instead of int

5. `generation/utils.py` line 532: `input_ids[:, -next_sequence_length:]`
   - Tensor-as-slice-index produces wrong (0-length) result

## Suggested Fix

In `_prefill()`, convert `past_length` to Python int after calling `get_seq_length()`:

```python
if (cache := model_kwargs.get("past_key_values")) is not None:
    past_length = cache.get_seq_length()
    if isinstance(past_length, torch.Tensor):
        past_length = int(past_length.item())
```

This is safe because:
- `cumulative_length` remains a tensor on the model (torch.compile compatibility preserved)
- Only the local variable in `_prefill` is converted
- On CUDA (where `get_seq_length()` may already return int): isinstance check is False → no-op
- Restores the `int | None` type contract for `next_sequence_length`

  This worked correctly in transformers 5.2.0 where _prefill() did not exist.
  The regression was introduced when _prefill was added (transformers >= 5.5.0)
  which introduced cache-aware token slicing using cache.get_seq_length().

  In 5.2.0: generate() always passed full input_ids to model.forward (no slicing).
  In 5.5.3: _prefill slices input_ids based on cache.get_seq_length(), but doesn't
  handle the case where get_seq_length() returns a tensor instead of int.
