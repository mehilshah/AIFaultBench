# recovered-from-issue: https://github.com/huggingface/pytorch-image-models/issues/2712

TITLE
[BUG] reg_token excluded from group_matcher()/no_weight_decay() in Eva and VisionTransformer

BODY
**Describe the bug**
`Eva.group_matcher()` and `Eva.no_weight_decay()` in `timm/models/eva.py` omit `reg_token`, unlike the structurally identical `cls_token`. The same omission exists in `VisionTransformer.group_matcher()`/`no_weight_decay()` in `timm/models/vision_transformer.py`.

Consequence: under layer-wise LR decay, `reg_token` matches no group in `group_matcher()`'s regex and falls into the last (deepest) group, giving it `lr_scale=1.0` (max, undecayed) instead of the the same minimum scale `cls_token` and `pos_embed` get. It would also receive weight decay by default, unlike `cls_token`/`pos_embed`.

**To Reproduce**
```python
import timm
from timm.optim._optim_factory import create_optimizer_v2

model = timm.create_model("vit_small_patch16_dinov3.lvd1689m", pretrained=True, num_classes=0)
optimizer = create_optimizer_v2(model, opt="adamw", lr=1e-3, weight_decay=0.05, layer_decay=0.75)

id_to_name = {id(p): n for n, p in model.named_parameters()}
for i, group in enumerate(optimizer.param_groups):
    names = [id_to_name[id(p)] for p in group["params"] if id(p) in id_to_name]
    print(f"group {i}: lr_scale={group['lr_scale']:.4f}, names={names}")
```

**Expected behavior**
`reg_token` should be assigned to the same group as `cls_token` (group 0), with the same minimum `lr_scale` (`0.0238`), not isolated in its own group at `lr_scale=1.0000` (the maximum in the model). It should also be excluded from weight decay, consistent with `cls_token` and `pos_embed`.
