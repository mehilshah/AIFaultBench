### Reproduction Steps / Example Code (Python)

```python
import os

os.environ.setdefault("FIREWORKS_API_KEY", "fake-key")  # offline repro, no network needed

from langchain_fireworks import ChatFireworks

llm = ChatFireworks(model="accounts/fireworks/models/kimi-k2-instruct")

# llm_output dicts exactly as _create_chat_result stores them for two Fireworks
# responses. Fireworks returns nested usage details; the second response here
# hits the prompt cache:
llm_outputs = [
    {
        "token_usage": {
            "prompt_tokens": 32,
            "completion_tokens": 51,
            "total_tokens": 83,
            "prompt_tokens_details": {"cached_tokens": 0},
        },
        "model_name": "accounts/fireworks/models/kimi-k2-instruct",
    },
    {
        "token_usage": {
            "prompt_tokens": 44341,
            "completion_tokens": 10,
            "total_tokens": 44351,
            "prompt_tokens_details": {"cached_tokens": 41518},
        },
        "model_name": "accounts/fireworks/models/kimi-k2-instruct",
    },
]

llm._combine_llm_outputs(llm_outputs)

# The end-to-end trigger against the live API is any batched call, e.g.
# llm.generate([[HumanMessage("a")], [HumanMessage("b")]]) — generate() collects
# the per-prompt llm_output dicts and calls _combine_llm_outputs on them.
```

### Description

`ChatFireworks._combine_llm_outputs` (`libs/partners/fireworks/langchain_fireworks/chat_models.py:956`) accumulates token usage with a plain `overall_token_usage[k] += v`, which assumes every usage value is an int.

But `_create_chat_result` stores the raw `response["usage"]` dict in `llm_output["token_usage"]` (line ~1085), and Fireworks chat completions include nested dicts there — `"prompt_tokens_details": {"cached_tokens": ...}` (see e.g. the response samples in BerriAI/litellm#25950, which show `prompt_tokens_details: {"cached_tokens": 41518}` from Fireworks). So as soon as `generate()` runs more than one prompt in a batch, combining the second output hits `dict += dict` and raises `TypeError`.

Two variants of the same problem:
* `prompt_tokens_details` present in both outputs → `TypeError: unsupported operand type(s) for +=: 'dict' and 'dict'`
* Fireworks can also return `"prompt_tokens_details": null`, which poisons `overall_token_usage` with `None` and blows up the same way on the next output.

This is the same bug that was reported for `langchain-mistralai` in #38482 — fireworks has a copy of the same naive loop. `langchain-openai` already solved this: its `_combine_llm_outputs` skips `None` values and merges nested dicts recursively via `_update_token_usage` (`libs/partners/openai/langchain_openai/chat_models/base.py:486`).

Fix is ready in #38646, mirroring the `langchain-openai` approach (`_update_token_usage` helper + `None` skip) with parametrized unit tests; `make format lint test` green in `libs/partners/fireworks` (118 passed). Could a maintainer assign this to me so the PR can be reopened?
