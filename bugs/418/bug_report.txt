# recovered-from-issue: https://github.com/pyg-team/pytorch_geometric/issues/10163

TITLE
Inconsistent implementation of bias in `nn.conv.TransformerConv`

BODY
### 🐛 Describe the bug

## Main issue
The `bias` argument is not being passed to the instantiation of `self.lin_value`, `self.lin_query`, and `self.lin_key`.

## Explanation
In `nn.conv.TransformerConv`, the `bias` argument is not being passed to `self.lin_value`, `self.lin_query`, and `self.lin_key`, corresponding to $W_2$, $W_3$, and $W_4$ in the docstring of the module. However, it is being passed to `self.lin_skip` corresponding to $W_1$. 

This is inconsistent behavior that does not align with the expectations of setting the `bias` parameter. It is unintuitive that the `bias` parameter only affects some of the model weights.

For very specific application such as [Deep One-Class Classification](https://proceedings.mlr.press/v80/ruff18a.html) (**Proposition 2**, specifically), it is a requirement that the model does not have any bias terms. The current implementation does not allow for this.

## Suggested fix
The suggested fix is to simply pass the `bias` argument to the instantiations of `self.lin_value`, `self.lin_query`, and `self.lin_key`. 
```
self.lin_key = Linear(in_channels[0], heads * out_channels, bias=bias)
self.lin_query = Linear(in_channels[1], heads * out_channels, bias=bias)
self.lin_value = Linear(in_channels[0], heads * out_channels, bias=bias)
```
