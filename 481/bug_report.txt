# recovered-from-issue: https://github.com/pyro-ppl/numpyro/issues/2041

TITLE
bug: `WishartCholesky.infer_shapes` assumes tuples instead of supporting arrays

BODY
### Bug Description

The `WishartCholesky` distribution accepts `scale_matrix`, `rate_matrix`, and `scale_tril` as array-type arguments, as seen in the [distribution's argument constraints](https://github.com/pyro-ppl/numpyro/blob/7a3c24ff4b072f3f3df6c0ef9494d1635753c53d/numpyro/distributions/continuous.py#L3092-L3094). However, the `infer_shapes` class method handles these parameters as if their shapes can be used directly like tuples of integers, which is inconsistent.

In particular, the following line in `infer_shapes` is problematic:

https://github.com/pyro-ppl/numpyro/blob/7a3c24ff4b072f3f3df6c0ef9494d1635753c53d/numpyro/distributions/continuous.py#L3240-L3241

### Steps to Reproduce

Using values from [test_distributions.py](https://github.com/pyro-ppl/numpyro/blob/7a3c24ff4b072f3f3df6c0ef9494d1635753c53d/test/test_distributions.py#L869-L873):

```python
from jax import numpy as jnp
from numpyro.distributions import WishartCholesky

concentration = jnp.array([4.0, 5.0])
scale_matrix = jnp.array([[[1.0, 0.5], [0.5, 1.0]]])

# This will raise a TypeError
WishartCholesky.infer_shapes(concentration, scale_matrix=scale_matrix)
```

### Expected Behavior

The method should extract `.shape` or use `jnp.shape(matrix)` instead of slicing the JAX array directly.
