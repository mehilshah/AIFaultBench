### Reproduction

`Qwen3_5TextConfig.base_model_tp_plan` only covers `self_attn.*` and `mlp.*` layers:

```python
base_model_tp_plan = {
    "layers.*.self_attn.q_proj": "colwise",
    "layers.*.self_attn.k_proj": "colwise",
    "layers.*.self_attn.v_proj": "colwise",
    "layers.*.self_attn.o_proj": "rowwise",
    "layers.*.self_attn.q_norm": "replicated_with_grad_allreduce",
    "layers.*.self_attn.k_norm": "replicated_with_grad_allreduce",
    "layers.*.mlp.gate_proj": "colwise",
    "layers.*.mlp.up_proj": "colwise",
    "layers.*.mlp.down_proj": "rowwise",
}
```

Qwen3.5 is a hybrid model: roughly 75% of its decoder layers are `linear_attention` layers backed by `Qwen3_5GatedDeltaNet` (Gated Delta Net / GDA). These layers have their own projection matrices (`in_proj_qkv`, `in_proj_z`, `in_proj_b`, `in_proj_a`, `out_proj`) that are absent from `base_model_tp_plan`. This produces two failures at TP>1:
**Failure 1: OOM when loading the model at TP>1**

The `linear_attn` weights are not sharded, so each rank holds a full copy. For `Qwen3.5-9B` at TP=4 this causes an out-of-memory error before any inference starts.

**Failure 2: RuntimeError during `model.generate()`**

Adding the `linear_attn` projections with the same `"colwise"` / `"rowwise"` pattern as `self_attn` does not fix this. `Qwen3_5GatedDeltaNet.forward` passes `in_proj_qkv`'s output directly through a depthwise `Conv1d` (with `groups=conv_dim`, where `conv_dim = key_dim*2 + value_dim = 8192`). With plain `"colwise"` TP, each rank receives only `conv_dim/TP = 2048` channels, but the `Conv1d` weight expects `8192`. A `torch.split([key_dim, key_dim, value_dim])` immediately after the conv has the same requirement.

```
RuntimeError: convolution(): expected the second dimension of the weight tensor
of shape [8192, 1, 4] to be 0 (2048 in channels divided by 8192 groups), got 1
```

### Root cause

`base_model_tp_plan` in `Qwen3_5TextConfig` is incomplete: it has no entries for any `linear_attn.*` submodule. Because roughly 75% of the model's layers use `linear_attention`, a large fraction of the parameters are not sharded at all when `tp_plan="auto"` is requested.

### Proposed fix

**File to edit: `src/transformers/models/qwen3_5/modular_qwen3_5.py`** (`configuration_qwen3_5.py` is auto-generated from it. The header says "Do NOT edit this file manually"; CI regenerates it from the modular source.)

Add `"colwise_gather_output"` entries for all `linear_attn` projections. `"colwise_gather_output"` is `ColwiseParallel(gather_output=True)`: the weight matrix is sharded across ranks (fixing the OOM), and the output activation is all-gathered before the next operation, so the forward pass sees the full tensor.

```python
base_model_tp_plan = {
    # ... existing self_attn and mlp entries unchanged ...
    "layers.*.linear_attn.in_proj_qkv": "colwise_gather_output",
    "layers.*.linear_attn.in_proj_z":   "colwise_gather_output",
    "layers.*.linear_attn.in_proj_b":   "colwise_gather_output",
    "layers.*.linear_attn.in_proj_a":   "colwise_gather_output",
    "layers.*.linear_attn.out_proj":    "colwise_gather_output",
}
```

`conv1d` is a `nn.Conv1d`, not a `nn.Linear`, so it does not appear in the TP plan. With `colwise_gather_output` on `in_proj_qkv`, the activations are gathered before `conv1d` runs, so the conv layer needs no TP plan entry.

### Why not `"colwise"` / `"rowwise"` (the self_attn pattern)?

The `self_attn` pattern works because `q/k/v_proj` outputs feed into independent per-head computations that decompose naturally across ranks, and `o_proj` with `"rowwise"` expects a sharded input from the preceding colwise-sharded value projection. The GDA forward pass does not have this property. `in_proj_qkv`'s output is a single concatenated `[Q, K, V]` tensor fed directly into a depthwise conv and then split. Neither operation is rank-decomposable. `"colwise_gather_output"` handles this by sharding the weights and inserting an all-gather before those ops.
