### 🐛 Describe the bug

MiniMax-M3 checkpoints quantized with [AWQ](https://huggingface.co/cyankiwi/MiniMax-M3-AWQ-INT4) or [GPTQ](https://huggingface.co/Sebesky/MiniMax-M3-W4A16-GPTQ) (INT4 W4A16) fail at engine warmup with:

```
RuntimeError: Worker failed with error 'SWIGLUOAI_UNINTERLEAVE requires clamp_limit'
```

This error is identical to the NVFP4 issue #45624 (closed June 15), which was fixed by adding `clamp_limit` support to the NVFP4 MoE backends. The INT4 (WNA16) path appears to have the same gap.

 MiniMax-M3 uses `activation="swigluoai_uninterleave"` with `swiglu_limit=7.0` (from model config). The Marlin kernel is the only WNA16 backend that supports this activation format.
