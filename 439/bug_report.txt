### 🐛 Describe the bug

### Describe the bug

When running vLLM on WSL2 with an NVIDIA RTX 4050 Laptop GPU, engine initialization consistently fails with:

```text
RuntimeError: UVA is not available
```

The issue is reproducible with both the offline `LLM()` API and the OpenAI-compatible server (`vllm serve`), indicating the failure occurs during engine initialization rather than in a specific entrypoint.

The model configuration, tokenizer, scheduler, distributed initialization, and `EngineCore` all initialize successfully. The failure occurs while initializing the GPU worker, when `GPUModelRunnerV2` constructs a `RequestState` that attempts to allocate a `UvaBuffer`.

I also reproduced the issue with `VLLM_TRACE_FUNCTION=1` enabled. A trace log was successfully generated before the crash.

### Minimal reproduction

```python
from vllm import LLM, SamplingParams


def main():
    llm = LLM(
        model="HuggingFaceTB/SmolLM2-360M-Instruct",
        gpu_memory_utilization=0.5,
        max_model_len=1024,
        enforce_eager=True,
    )

    sampling_params = SamplingParams(
        temperature=0.7,
        max_tokens=100,
    )

    outputs = llm.generate(
        "Explain Retrieval-Augmented Generation.",
        sampling_params,
    )

    print(outputs[0].outputs[0].text)


if __name__ == "__main__":
    main()
```

### Expected behavior

The model should initialize successfully and generate a response.

### Actual behavior

The engine fails during initialization before any inference begins.

Relevant traceback:

The parent process then exits with:

```text
RuntimeError: Engine core initialization failed. See root cause above. Failed core proc(s): {}
```

### Additional observations

- `torch.cuda.is_available()` returns `True`.
- The GPU is detected correctly as `NVIDIA GeForce RTX 4050 Laptop GPU`.
- The model downloads successfully from Hugging Face.
- `nvidia-smi` shows no active CUDA compute processes before running vLLM.
- Reducing `gpu_memory_utilization` to `0.5`, setting `max_model_len=1024`, and enabling `enforce_eager=True` do not change the behavior.
- `VLLM_TRACE_FUNCTION=1` successfully generated a function trace log before the crash.

Is this expected behavior on WSL2, or could this be a regression related to the V2 model runner's use of `UvaBuffer`?
