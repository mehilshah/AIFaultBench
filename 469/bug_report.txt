### 🐛 Describe the bug

While testing the PR #47217, I observed that gemma-4 family suffers accuracy issue for long context with images in it when using FA4 cutedsl SM90 (the default attention backend for SM90 NVIDIA GPUs) as attention backend, but it works normal without accuracy drop for triton attention backend.

# Symptom

When FA4(`--attention-backend FLASH_ATTN`) is used, the model answers normal for the first 3 vision turns, then starts gibberish at the final turn:

- gemma-4 31b dense model: `'s 202 la l'en ...`
- gemma-4 26b MoE model: `3-4-0-1-5-...`

When triton(`--attention-backend TRITON_ATTN`) is used, the model answers normal for all 4 turns for both dense and MoE model. (though it becomes incredibly slow at the final turn)

If the conversation includes only text inputs (e.g. one can easily adapt the "NIAH-type puzzle" above to generate such one), both FA4 and triton attention backend works normal (answers the puzzle correctly).

I first thought that this issue is introduced by the PR branch, but it turns out that the accuracy bug remains in the main branch 93d8f834d as well.
