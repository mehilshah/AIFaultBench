Title: ValueError with numpy arrays in embed defs
Date: 2026-01-26T01:03:52+00:00
URL: https://github.com/marimo-team/marimo/issues/7969

Description:
### Describe the bug

When the `defs` given to an embed are numpy arrays, a `ValueError` may pop up when given an array with different shape than before. This also hints another bug where a new def value may not propagate.

* Edit/run the provided example `embed_np_a.py`
* Change selection in the dropdown
* Expected: updated result
* Actual: exception -

```
ValueError
The truth value of an array with more than one element is ambiguous. Use a.any() or a.all()
See the console area for a traceback.
```

This probably happens because numpy overridden `==` to compare elements in arrays rather than the whole array. Marimo should probably do some kind of actual comparison which results with a boolean rather than `==` which is overridden by popular libraries.

### Code to reproduce

As this is an embed issue, two short notebooks are provided, the external `embed_np_a.py`:

```Python
import marimo

__generated_with = "0.19.6"
app = marimo.App(width="full")


@app.cell
def _():
    import marimo as mo
    import numpy as np
    return mo, np


@app.cell
def _():
    import embed_np_b
    return (embed_np_b,)


@app.cell
def _(mo, np):
    dropdown = mo.ui.dropdown(
        {"ones(1)": np.ones(1), "zeros(2)": np.zeros(2)}, value="ones(1)"
    )
    dropdown
    return (dropdown,)


@app.cell
async def _(dropdown, embed_np_b):
    embed = await embed_np_b.app.embed(defs={"arr": dropdown.value})
    embed.output
    return


if __name__ == "__main__":
    app.run()
```
