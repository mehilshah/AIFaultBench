Title: [BUG]  Memory-Mapped Storage fails to zero out missing tensors when reusing scratch dir path
Date: 2024-09-16T06:35:01+00:00
URL: https://github.com/pytorch/rl/issues/2437

Description:
## Describe the bug

When writing a tensor dict to memory-mapped storage, the expected behavior is for missing tensors to be replaced with tensors initialized to zero. However, when reusing a previously allocated memory-mapped storage path, missing tensors are not overwritten with zeros but instead retain stale data from previously saved tensor dictionaries. This leads to unexpected behavior when attempting to load tensor dictionaries with incomplete keys.


## To Reproduce
```python
import torch
from tensordict import TensorDict
from torchrl.data import LazyMemmapStorage

storage_path = '/tmp/new'
storage = LazyMemmapStorage(1000, scratch_dir=storage_path)
data1 = TensorDict({"a": torch.zeros(5, 3) + 1, "d": torch.zeros(5, 1) + 1}, [5])
storage.set(range(5), data1)
data2 = TensorDict({"a": torch.zeros(1, 3) + 2}, [1])
storage.set(range(5,6), data2)
print("Key 'd':", storage["d"])
# Output: Key 'd': MemoryMappedTensor([[1.], [1.], [1.], [1.], [1.], [0.]])

# rewrite with new data
storage = LazyMemmapStorage(1000, scratch_dir=storage_path)
data1 = TensorDict({"a": torch.zeros(1, 3) + 1, "d": torch.zeros(1, 1) + 1}, [1])
storage.set(range(1), data1)
data2 = TensorDict({"a": torch.zeros(5, 3) + 2}, [5])
storage.set(range(1,6), data2)
print("Key 'd':", storage["d"])
# Output: Key 'd': MemoryMappedTensor([[1.], [1.], [1.], [1.], [1.], [0.]])
# expected 'd': MemoryMappedTensor([[1.], [0.], [0.], [0.], [0.], [0.]])
```

This is probably a bad use of mapped storage. But in my case, I am using the replaybuffer with a mapped storage with scratch_dir set to a path 'on direct-attached storage' (just so it will be fast), but I was using the same path for different runs of same code.

When I run the code second time (with same path), I am seeing unexpected values.

## Expected behavior
I am not sure of the policy, whether it is expected that a tensor dict with missing key can be updated to a storage successfully. IMO It may be a good practice to force developer to provide full tensordict, or atleast make sure the storage rewrites values whenever a partial dict is updated.
