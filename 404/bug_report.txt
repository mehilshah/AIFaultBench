# recovered-from-issue: https://github.com/jax-ml/jax/issues/38622

TITLE
jax.scipy.stats.poisson.cdf returns nan at k=inf for positive mu

BODY
### Description

`jax.scipy.stats.poisson.cdf(k=np.inf, mu, loc=0.0)` returns `nan` for
positive values of `mu`, while SciPy returns `1.0`.

Examples:

```text
poisson.cdf(k=inf, mu=1.0): scipy=1.0, jax=nan
poisson.cdf(k=inf, mu=2.0): scipy=1.0, jax=nan
```

This appears to be a boundary handling mismatch for the CDF at `k=+inf`. The
distribution parameters are valid:

```python
mu = 1.0
loc = 0.0
```

The case `mu=0.0` is handled consistently by JAX and SciPy. The mismatch appears
for positive finite `mu`.

## Origin

Found via property-based testing derived from:

```text
jax/tests/lax_scipy_stats_test.py
  ::LaxBackedScipyStatsTests::testPoissonCdf
```

The property uses a reference oracle: `jax.scipy.stats.poisson.cdf` is compared
against `scipy.stats.poisson.cdf` in NaN classification and finite values for
valid inputs.

The existing JAX test clips `mu` to be at least `0.1` (`np.clip(np.abs(mu),
a_min=0.1, a_max=None)`), so `mu=0`, negative `mu`, and `nan`/`inf` values of
`k` are never exercised. Testing explicitly with `mu ∈ {0.0, 1.0}` and
`k ∈ {-inf, -1.0, 0.0, 0.5, 1.0, nan, inf}` reproduces the failure
deterministically at `k=+inf` for every positive `mu`, while `k=-inf` (used as
a control case alongside `k=+inf`) and all other tested combinations behave as
expected in both libraries.

The failing case uses valid distribution parameters:

```python
k = np.inf
mu = 1.0
loc = 0.0
```

The same behavior also appears with other positive finite values of `mu`, such
as `mu=2.0`.

## Verification

The Poisson CDF is:

```text
P(X <= k)
```

For any finite valid `mu >= 0`, a Poisson random variable only takes finite
nonnegative integer values. Therefore, at `k=+inf`, all possible outcomes are
included:

```text
P(X <= +inf) = 1.0
```

This follows directly from the definition of the CDF. SciPy returns `1.0`, while
JAX currently returns `nan` for positive `mu`.

## Minimal reproducer

```python
import numpy as np
import scipy.stats
import jax
import jax.numpy as jnp
import jax.scipy.stats

jax.config.update("jax_enable_x64", True)

cases = [
    (np.float32(np.inf), np.float32(0.0), np.float32(0.0)),
    (np.float32(np.inf), np.float32(1.0), np.float32(0.0)),
    (np.float32(np.inf), np.float32(2.0), np.float32(0.0)),
    (np.float32(np.inf), np.float32(1.0), np.float32(1.0)),

    # Control cases
    (np.float32(-np.inf), np.float32(1.0), np.float32(0.0)),
    (np.float32(np.nan), np.float32(1.0), np.float32(0.0)),
    (np.float32(-1.0), np.float32(1.0), np.float32(0.0)),
    (np.float32(0.0), np.float32(0.0), np.float32(0.0)),
    (np.float32(0.0), np.float32(1.0), np.float32(0.0)),
    (np.float32(1.0), np.float32(1.0), np.float32(0.0)),
    (np.float32(2.0), np.float32(1.0), np.float32(0.0)),
    (np.float32(0.5), np.float32(1.0), np.float32(0.0)),
]

for k, mu, loc in cases:
    scipy_result = scipy.stats.poisson.cdf(
        np.array(k), np.array(mu), loc=np.array(loc)
    )
    jax_result = jax.scipy.stats.poisson.cdf(
        jnp.array(k), jnp.array(mu), jnp.array(loc)
    )
    jit_result = jax.jit(
        lambda k_, mu_, loc_: jax.scipy.stats.poisson.cdf(k_, mu_, loc_)
    )(jnp.array(k), jnp.array(mu), jnp.array(loc))

    print(f"k={k!r}, mu={mu!r}, loc={loc!r}")
    print(f"  scipy: {scipy_result}")
    print(f"  jax:   {jax_result}")
    print(f"  jit:   {jit_result}")
    print()
```

## Expected behavior

At `k=+inf`, the CDF would be expected to include the full probability mass:

```text
k=np.float32(inf), mu=np.float32(1.0), loc=np.float32(0.0)
  scipy: 1.0
  jax:   1.0
  jit:   1.0

k=np.float32(inf), mu=np.float32(2.0), loc=np.float32(0.0)
  scipy: 1.0
  jax:   1.0
  jit:   1.0
```

## Actual behavior

```text
k=np.float32(inf), mu=np.float32(1.0), loc=np.float32(0.0)
  scipy: 1.0
  jax:   nan
  jit:   nan

k=np.float32(inf), mu=np.float32(2.0), loc=np.float32(0.0)
  scipy: 1.0
  jax:   nan
  jit:   nan

k=np.float32(inf), mu=np.float32(1.0), loc=np.float32(1.0)
  scipy: 1.0
  jax:   nan
  jit:   nan
```

## Additional cases

```text
k= inf, mu=0.0: scipy=1.0, jax=1.0  OK
k= inf, mu=1.0: scipy=1.0, jax=nan  ← mismatch
k= inf, mu=2.0: scipy=1.0, jax=nan  ← mismatch

k=-inf, mu=1.0: scipy=0.0, jax=0.0  OK
k= nan, mu=1.0: scipy=nan, jax=nan  OK
k=-1.0, mu=1.0: scipy=0.0, jax=0.0  OK

k=0.0, mu=1.0: finite values are close within tolerance  OK
k=1.0, mu=1.0: finite values are close within tolerance  OK
k=2.0, mu=1.0: finite values are close within tolerance  OK
```

The mismatch appears specific to `k=+inf` with positive finite `mu`. The tested
non-infinite and negative-infinite control cases match SciPy in NaN/inf
classification and are close within tolerance for finite values.
