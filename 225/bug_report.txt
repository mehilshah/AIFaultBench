Title: [Bug]: Docker - JWT authentication not enforced when enabled - requests without tokens are incorrectly allowed
Date: 2025-08-27T04:42:58+00:00
URL: https://github.com/unclecode/crawl4ai/issues/1442

Description:
### crawl4ai version

0.7.4

### Expected Behavior

When jwt_enabled: true is set in config.yml:
  - Requests WITHOUT an Authorization header should receive a 401 Unauthorized error
  - Requests with an INVALID token should receive a 401 Unauthorized error
  - ONLY requests with a valid JWT Bearer token should be allowed through

### Current Behavior

When jwt_enabled: true is configured:
  - Requests WITHOUT any Authorization header are incorrectly allowed and processed successfully
  - Requests with INVALID tokens correctly receive 401 errors
  - Requests with VALID tokens work as expected

  Root cause: In deploy/docker/auth.py line 34-35, when credentials is None (no Authorization header), the function returns None instead of raising an HTTPException, effectively bypassing JWT protection
  entirely.
