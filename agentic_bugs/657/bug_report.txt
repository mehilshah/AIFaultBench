### Reproduction Steps / Example Code (Python)

```python
from langchain_anthropic import ChatAnthropic
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_core.messages.content import create_text_block

llm = ChatAnthropic(model_name="claude-haiku-4-5", output_version="v1", max_tokens=16)

# create_text_block() mints an `id` (e.g. "lc_<uuid4>") on the block.
system_message = SystemMessage(content_blocks=[create_text_block("You are a helpful assistant.")])
print("system block:", system_message.content_blocks)
# -> [{'type': 'text', 'text': 'You are a helpful assistant.', 'id': 'lc_fcd78d19-...'}]

llm.invoke([system_message, HumanMessage("Say hi.")])  # raises BadRequestError
```

### Description

`ChatAnthropic` handles `SystemMessage` content differently from every other message type, and the
difference leaks a LangChain-internal field onto the wire.

In [`langchain_anthropic.chat_models._format_messages`](https://github.com/langchain-ai/langchain/blob/76b4b2472a644acd399ddf3caa13242a2b289b02/libs/partners/anthropic/langchain_anthropic/chat_models.py#L490-L498), a system message with list content has its
blocks passed straight through as dicts:

```python
if message.type == "system":
    ...
    if isinstance(message.content, list):
        system = [
            block if isinstance(block, dict) else {"type": "text", "text": block}
            for block in message.content
        ]
```

Every other message type falls through to the branch below, which **rebuilds** each block
field-by-field and therefore drops keys Anthropic doesn't accept. The v1→native translation in
`_get_request_payload` doesn't help either — it only runs for `AIMessage` with
`response_metadata["output_version"] == "v1"`.

Because `create_text_block()` (and the other `create_*_block` factories) mint an `id` via
`ensure_id()`, any system message built from those factories — the natural way to build v1 content —
sends `{"type": "text", "text": ..., "id": "lc_<uuid4>"}` in the `system` field, and the API rejects
the unknown key.

Other providers already discard the `id` on this path, so the behavior is Anthropic-specific:

| Provider | system payload | `id` |
| --- | --- | --- |
| Anthropic | `[{'type': 'text', 'text': '...', 'id': 'lc_...'}]` | **leaks** |
| Google (`_parse_chat_history`) | `parts=[Part(text='...')]` | dropped |
| OpenAI (`_construct_responses_api_input`) | `[{'type': 'input_text', 'text': '...'}]` | dropped |

A secondary effect: `ChatAnthropic.get_num_tokens_from_messages` passes system content through as
the `system` kwarg too, so token counting against the same message fails for the same reason.

Suggested fix: give system blocks the same field-level rebuild the non-system branch performs (or at
minimum strip block `id`) so content produced by the `create_*_block` factories is accepted.
