### Description

## Summary

The `@task` decorator's checkpointing mechanism does not work when deploying via LangGraph API server because task-level checkpointing requires a compile-time checkpointer, but the API server:
1. Rejects custom checkpointers passed to `compile()`
2. Injects its checkpointer at runtime

This creates a silent failure where tasks re-execute on workflow resume, breaking durable execution guarantees.

## Current Documentation

The [Durable Execution docs](https://langchain-ai.github.io/langgraph/concepts/durable_execution/) state:

> "You can use tasks from both the StateGraph (Graph API) and the Functional API."

> "If a node contains multiple operations, you may find it easier to convert each operation into a task rather than refactor the operations into individual nodes."

The [Persistence docs](https://langchain-ai.github.io/langgraph/concepts/persistence/) state:

> "When using the LangGraph API, you don't need to implement or configure checkpointers manually - persistence is handled automatically by the platform."

These statements together imply @task will work with API server checkpointing, but it doesn't.

## Root Cause (from source analysis)

**langgraph/func/__init__.py** - `_TaskFunction` class:
- Stores `func`, `retry_policy`, `cache_policy`
- Does NOT store any checkpointer reference

**langgraph/pregel/_runner.py** - `_call()` function:
- Uses `schedule_task()` to check for cached task results
- `schedule_task` loads previous writes from `Pregel.checkpointer`
- If `Pregel.checkpointer = None` (compiled without checkpointer), task writes cannot be loaded
- Task re-executes even if API server saved the writes via runtime checkpointer

**The asymmetry:**
| Operation | Checkpointer Source | Works with Runtime Injection? |
|-----------|--------------------|-----------------------------|
| Node state SAVE | Runtime config | ✅ Yes |
| Node state LOAD | Runtime config | ✅ Yes |
| Task result SAVE | put_writes (possibly runtime) | Maybe |
| Task result LOAD | schedule_task → Pregel.checkpointer | ❌ No |

## Expected Behavior

One of:
1. @task checkpointing works with runtime-injected checkpointer (feature)
2. Documentation clearly states @task requires compile-time checkpointer and won't work with API server (docs fix)
3. API server allows compile-time checkpointers for graphs using @task (feature)

## Current Workarounds

1. **Use separate nodes instead of @task** for non-deterministic operations
2. **Use pure Functional API** (@entrypoint + @task) instead of StateGraph
3. **Deploy custom server** that compiles with checkpointer
