# recovered-from-issue: https://github.com/facebookresearch/detectron2/issues/1064

TITLE
Not able to index Instances with Int

BODY
## T.L.T.R
The length check in [instances.py](https://github.com/facebookresearch/detectron2/blob/master/detectron2/structures/instances.py#L71) causes problem when passes a scalar tensor (such as class id or score) in the ['\_\_getitem\_\_'](https://github.com/facebookresearch/detectron2/blob/master/detectron2/structures/instances.py#L116) method.

I have submitted a [pull request](https://github.com/facebookresearch/detectron2/pull/1065) to fix this issue if we consider `Instances` can be indexed with integers.
The basic idea is to convert an integer index to slice, to avoid type and shape check in `set` function.

## Instructions To Reproduce the Issue:

1. what changes you made (`git diff`) or what code you wrote
No changes are made, cloned from the master branch

2. how to reproduce this bug:
To reproduce this bug, simply run the following command under detectron2 repo directory.:
```
python tools/eval_image.py  --config-file configs/Detectron1-Comparisons/mask_rcnn_R_50_FPN_noaug_1x.yaml
```
Where the content of `eval_image.py` is:
```python
#!/usr/bin/env python

import urllib
import numpy as np
import cv2
import torch

from detectron2.config import get_cfg
from detectron2.engine import DefaultPredictor, default_argument_parser, default_setup


def setup(args):
    """
    Create configs and perform basic setups.
    """
    cfg = get_cfg()
    cfg.merge_from_file(args.config_file)
    cfg.merge_from_list(args.opts)
    cfg.freeze()
    default_setup(cfg, args)
    return cfg


if __name__ == "__main__":
    args = default_argument_parser().parse_args()
    print("Command Line Args:", args)
    cfg = setup(args)

    model = DefaultPredictor(cfg)
    url = "http://images.cocodataset.org/val2017/000000397133.jpg"
    resp = urllib.request.urlopen(url)
    image = np.asarray(bytearray(resp.read()), dtype="uint8")
    image = cv2.imdecode(image, cv2.IMREAD_COLOR)
    res = model(image)
    instances = res['instances']
    instances[0]
```
You will get a type erro message:
```shell
Traceback (most recent call last):
  File "tools/eval_image.py", line 36, in <module>
    instances[0]
  File "/home/wangxiny/Documents/detectron2_pull/detectron2/structures/instances.py", line 137, in __getitem__
    ret.set(k, v[item])
  File "/home/wangxiny/Documents/detectron2_pull/detectron2/structures/instances.py", line 71, in set
    data_len = len(value)
  File "/home/wangxiny/Python36_detectron2/lib/python3.6/site-packages/torch/tensor.py", line 445, in __len__
    raise TypeError("len() of a 0-d tensor")
TypeError: len() of a 0-d tensor
```
This should be a bug given that `Instances` class takes integer for indexing (In the line 119 of `detectron2/detectron2/structures/instances.py` , we have ` def __getitem__(self, item: Union[int, slice, torch.BoolTensor]) -> "Instances":` )

## Expected behavior:

An object of 'Instances' should be returned from the source `Instances` object with a given index.
